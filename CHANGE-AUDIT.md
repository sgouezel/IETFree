# The `change` audit: why each surviving `change` is there

Every `change` in `IETFree/` is tried by deleting it and compiling the module; this file records, for
each of them, the error the deletion produces — the reason it cannot simply be removed — or, where
the deletion compiles, that it has been removed.  Method: delete the statement, run `lake env lean`
on the module, keep the first error.  *Did not find an occurrence of the pattern* means a later `rw`
no longer matches; *not definitionally equal* or *motive is not type correct* means the goal is not
the target; *unsolved goals* means the next tactic no longer closes what is left.

The count and the line numbers are regenerated by `Addendum 246` (HISTORY.md), the fifth round:
Addenda 175–185 ran the audit, 215 and 223 re-pointed the line numbers, 232 removed six sites whose
replacement that round had found, and the placement, naming and `simp` passes of Addenda 244–246
moved others.  Every number below is the current one; a row whose `change` has gone is not kept.
This round found exactly one removable site — `WordData.lean:281`,
`change |A (Fin.last m) + B (Fin.last n)| ≤ 2 * K`, whose goal `rw [abs_le]` already matched — and
deleted it.
